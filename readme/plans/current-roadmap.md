# zcode-relay 当前路线图

日期：2026-08-22

## 当前阶段：阶段 0 基线与阶段 1 账号池

目标：在不改变现有协议转换行为的前提下，把单凭据核心改造成可测试的多账号运行时。

验收：

- 账号池能按 provider 管理至少两个假账号。
- 请求选择、租约、轮询和冷却状态可确定性测试。
- 认证失败、额度耗尽、限流和连接错误能按分类切换账号。
- 核心内部控制 API 可以管理账号和读取脱敏状态。
- 面板具备调用核心控制 API 的适配边界。

## 后续阶段

### 阶段 2：额度与用量

- 请求级 token usage 采集。
- provider 额度检查器。
- 周期刷新和健康状态。
- 面板用量统计与异常提示。

### 阶段 3：控制面联调

- zcode2api 页面接入核心控制 API。
- 核心与面板 Compose 编排。
- 内部密钥、健康检查和配置热加载。

### 阶段 4：灰度与发布

- 双实例或旧代理 fallback。
- 受控流量比例和回滚开关。
- Docker 镜像固定、CI、发布和远程 SHA 对账。
