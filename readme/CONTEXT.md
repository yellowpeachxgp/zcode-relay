# zcode-relay 上下文与不变量

## 产品定位

zcode-relay 是一个由管理面板和数据面核心组成的 ZCode 代理产品。

- 控制面：panel/zcode2api。
- 数据面：根目录 zcode-api。
- 上游：Z.AI 和 BigModel。

## 核心不变量

1. 所有真实用户流量必须经过核心数据面，面板不直接代理用户请求。
2. 核心是账号池、账号状态、请求租约和用量数据的唯一运行时权威。
3. 账号按 provider 分池；Z.AI 账号不能被 BigModel 请求选择，反之亦然。
4. 长连接和 SSE 请求中，面板操作不得终止或重置正在进行的核心请求。
5. 可重试的上游失败才允许切换账号；请求格式错误、模型不存在和客户端鉴权错误不得盲目换号。
6. 额度检查失败不能直接等价于凭据失效。
7. 任何面向浏览器的响应、日志和指标都必须脱敏。
8. 旧的 zcode-api 协议转换行为必须保持：Anthropic、OpenAI、Responses 和流式事件不能因为账号池改造而漂移。
9. 重启后账号池和禁用、冷却、失效状态必须可恢复；轮询游标可以安全重置。
10. 本项目主线程完成全部分析、开发、测试、提交和推送，不使用 subagent。

## 术语

- account：一个 provider 凭据及其运行状态。
- pool：同一 provider 下的账号集合。
- lease：一次请求占用一个账号的短生命周期租约。
- quota：上游账号套餐或额度快照。
- usage：一次请求或一段时间内实际消耗的输入、输出 token。
- challenge：验证码、WAF 或客户端签名挑战，不等价于无效凭据。
